# Xceptional Place Hotel — Smart Hotel Website (Django + Tailwind)

A full-stack demo of a "smart" luxury hotel website: real-time-style booking engine,
an in-stay "My Stay" guest services portal, an AI concierge chat widget, and
role-based staff dashboards — built with Django, HTML/Tailwind CSS, and vanilla JS.

## Quick Start

```bash
# 1. Create a virtual environment (recommended)
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Apply migrations (the included db.sqlite3 already has demo data,
#    but this is safe to re-run)
python manage.py migrate

# 4. (Optional) Re-seed fresh demo data — this WIPES and recreates
#    all rooms, bookings, menu items, staff accounts, etc.
python manage.py seed_data

# 5. Run the dev server
python manage.py runserver

# 6. Visit
http://127.0.0.1:8000/
```

The project ships with a populated `db.sqlite3` and `media/` folder, so it works
out of the box — no seeding required unless you want to reset the data.

## What's Implemented (Demo Scope)

- **Booking engine** — room browsing/filtering, a 5-step booking flow (dates →
  room → guest details → add-ons → review/payment), reference-code generation,
  self-service manage/cancel by reference + email. Payment is **mocked**
  (marks the booking paid instantly) — no live Paystack keys are wired in.
- **Guest "My Stay" portal** — reference-code login, tabbed ordering for food,
  laundry, housekeeping and extras, with a visual New → Acknowledged →
  In Progress → Ready → Delivered status tracker per request.
- **AI concierge widget** — a rule-based chat assistant on every page (client-
  side JS) that answers common questions and "places" conversational orders.
  This is a scripted demo, not a live LLM integration.
- **Role-based dashboards** — separate logins/views for Super Admin (analytics
  overview, sentiment summary, staff directory), Front Desk (arrivals/
  departures/check-in-out, all bookings), Kitchen, Laundry and Housekeeping
  (each sees only their own order queue and can advance order status).
- **Events inquiry-to-quote** flow, **contact** form, **blog**, and **gallery**
  all persist to the database via Django models/admin.
- **Mock data**: realistic rooms, menu items, amenities, testimonials,
  bookings, service orders, staff shifts — all generated by
  `core/management/commands/seed_data.py`, using your supplied photos.

## What's Intentionally Stubbed / Not Wired Up

These were named in the brief as v2 items or require credentials/services
this environment doesn't have — the UI and data model support them, but the
live integration isn't connected:

- **Real Paystack payments** — swap the mock payment step in
  `bookings/views.py::book()` for the Paystack Inline JS + verify-transaction
  API once you have live/test keys.
- **Live LLM-powered AI concierge** — replace `static/js/site.js`'s `aiReply()`
  function with a call to your LLM provider of choice (the front end is
  already structured to drop this in).
- **WhatsApp Business API** — links currently point to a `wa.me` deep link;
  a real integration needs the Business API/webhooks.
- **Email/SMS confirmations** — booking/order confirmations are simulated via
  on-screen messaging; wire up `django.core.mail` + an SMS/WhatsApp provider.
- **AI dynamic pricing, multi-property support, IoT room keys** — flagged in
  the brief as v2/needs-occupancy-history items; not built.

## Notes

- Styling uses the **Tailwind CDN build** with an inline config (black/white/
  grey/gold palette, Playfair Display + Inter fonts) for simplicity — for a
  production deploy, switch to a compiled Tailwind build.
- `DEBUG = True` and `ALLOWED_HOSTS = ['*']` are set for demo convenience —
  tighten both before deploying anywhere public.
- Icons are from [Lucide](https://lucide.dev) (loaded via CDN).
